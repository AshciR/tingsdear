# Part 3 — UI (`+page.svelte`)

## Context

The final piece of the tracer: a single-page Svelte 5 (runes) UI that walks the user through `upload → parsing → verify → done`. The verify step is the key UX moment — it shows the parser's output, lets the user correct it (because the model isn't perfect, especially on Jamaican receipts with discount/package lines), and on confirm posts to the save route from Part 2.

## Implementation

### State

```ts
let view = $state<'upload' | 'parsing' | 'verify' | 'done'>('upload');
let file = $state<File | null>(null);
let parsed = $state<ParsedReceipt | null>(null);
let saved = $state<{ saved: number; chainId: number; locationId: number } | null>(null);
let errorMsg = $state<string | null>(null);
```

Derived preview URL with `$effect` cleanup:

```ts
let previewUrl = $state<string | null>(null);
$effect(() => {
  if (!file) { previewUrl = null; return; }
  const url = URL.createObjectURL(file);
  previewUrl = url;
  return () => URL.revokeObjectURL(url);
});
```

### Views

- **upload**: `<input type="file" accept="image/*,application/pdf" capture="environment">` bound via `onchange` to set `file`. Show preview (image tag or "PDF: filename"). Submit button → `view='parsing'`; POST `FormData` with `file` to `/api/receipts/parse`; on success, set `parsed`, `view='verify'`; on failure, set `errorMsg`, `view='upload'`.
- **parsing**: spinner + the filename. No interaction.
- **verify**: editable form:
  - Text input bound to `parsed.supermarket_name`.
  - Date input bound to `parsed.purchase_date`.
  - Per-line-item row: name (text), quantity (number), unit_price (number), total (number), delete button. Rows where `flagged === true` get a yellow border + a tooltip "Looks like a non-product line — review before saving" and start with a checkbox pre-checked to indicate the user should review.
  - "Add row" button appends a blank line item (`{ name: '', quantity: 1, unit_price: 0, total: 0, flagged: false }`).
  - Confirm button → POST `JSON.stringify(parsed)` to `/api/receipts/save`; on success set `saved`, `view='done'`; on failure set `errorMsg` and stay.
- **done**: "Saved {saved.saved} items to chain #{saved.chainId} / location #{saved.locationId}." Button "Scan another" → reset all state, `view='upload'`.

### Style

Tailwind utilities. Keep it functional, not polished — this is a tracer. Centered max-w-2xl column. Flagged rows: `border-yellow-400 bg-yellow-50`.

### Constraints

- Svelte 5 runes only — no stores, no `$:`.
- No client-side validation beyond required-field markers; the server re-validates via Zod.
- Import the `ParsedReceipt` type from `$lib/server/receipt-parser.ts` (type-only import is fine in a browser file).

### Manual end-to-end

Container `tdd-pg-test` running, `RECEIPT_EXTRACTOR` set, `yarn dev`:

1. Upload `training-data/receipt-1.jpg`.
2. Observe spinner, then verify form prefilled with chain, date, items.
3. Edit a row, delete a flagged "Package Price" row, click Confirm.
4. See "Saved N items…". Query DB (DataGrip `jdbc:postgresql://localhost:55432/tdd`) to confirm:
   - One `supermarket_chain` row with the chain name.
   - One `supermarket_location` row, `name = 'Default'`.
   - N `item` rows with `manufacturer_id` pointing at "Unknown".
   - N `price` rows, `source = 'receipt_ocr'`, timestamp = purchase date at UTC midnight.
5. Re-upload the same receipt and re-save; confirm item count stable, price count doubled (no dedupe by design).
